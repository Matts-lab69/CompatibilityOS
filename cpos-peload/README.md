# cpos-peload parser

This isolated experimental C component accepts PE32+ AMD64 images only. The parser and `pe_stage` remain non-executable and suitable for parser/fuzz testing. `pe_execute_fixture` is a separate Linux/x86-64 fixture runner: it applies AMD64 DIR64 relocations, resolves exact `(module, symbol)` pairs only from the caller-provided allowlist, maps from anonymous memory, and changes section permissions without permitting a section to be both writable and executable. Entry invocation is opt-in and uses a deliberately narrow, no-argument fixture contract.

The fixture runner supports bounded process-attach TLS callbacks, but not static TLS or TEB/PEB emulation. It does not support arbitrary PE files, OS DLLs, Linux library fallback, Windows process initialization or exception unwinding. Entrypoint code runs natively; use only project-owned synthetic fixtures in isolated CI. Do not invoke untrusted images. Unsupported platforms return `PE_UNSUPPORTED`.

CI runs `make check` for synthetic parser inputs, `make check-exec` for isolated execution, and `make fuzz` for at least ten million libFuzzer iterations with synthetic seeds and one MiB per input. Targets use AddressSanitizer and UndefinedBehaviorSanitizer. Do not build or execute them locally.

`make build-dll-fixtures` cross-builds (but does not run) `fixture_dll.exe`, `cposapi.dll`, and `cposdep.dll`. The EXE imports one direct API export, an export forwarded by `cposapi.dll` to `cposdep.dll`, and an API that reports the `cposapi.dll` process-attach state. The API's direct export also calls the dependency, which itself imports `CposFixtureHostReady` from the host allowlist. `check-exec` supplies that exact `(module, symbol)` pair and verifies DLL dependency loading, attach order, forwarded export resolution, and allowlisted host binding from a DLL. `fixture_dll.exe` traps unless the API returns `0x2b`, the API attach-state export returns `0x51`, and the forwarded dependency export returns `0x2a`. Static TLS and process-attach TLS callbacks are EXE-only; DLLs with a TLS directory are rejected.

`make build-delay-fixture` cross-builds `fixture_delay.exe` and registers its RVA-form delay-import directory. `check-exec` runs the fixture with the same explicitly supplied DLLs. The loader checks that the slot initially holds the fixture resolver, that the first call binds `cposdep.dll` / `CposDependencyValue`, and that the second call uses the bound address without invoking the resolver again. This is delayed symbol binding for one no-argument fixture, not lazy module loading or general delay-import support. Other delay-import directories are rejected. The preparation utility is for this project-owned fixture only.
